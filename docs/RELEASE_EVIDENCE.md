# Offline release evidence

`tools/release-check.ps1` reads the executable inventory in
`tools/release-test-inventory.json`. The inventory checker is explicitly
classified as a checker called by the generated-lists phase; its standalone
regression covers fresh tracked checkouts, pending tests, invalid phases and
stale exclusions. Pending Lua, Python and PowerShell tests are discovered.

## Schema coverage

`tools/menu_schema_coverage_receipt.json` is compact committed evidence from a
fully audited declaration projection. It contains generator/projection versions,
the normalized source hash, the portable projection content hash (checkout prefixes normalized), issue count, totals and
per-client proven/profile/initial/all-declaration counts. The source digest
includes the generator, product graphs, indexes and referenced build harnesses.
`tools/scorecard.py` verifies it read-only without needing the ignored large
`tools/menu_schema_coverage.json`. Missing, inconsistent or stale receipts fail.
The receipt is reviewed evidence committed with its inputs, not a signature or
independent proof of a maliciously rewritten receipt.

After a deliberate source change, run Lua 5.1 inside the shared check slot:

```
python tools/menu_schema_coverage.py --write --lua <lua51>
```

`--write-receipt` audits an existing current full projection before writing only
the compact receipt. `--check-receipt` is read-only. Release-check keeps the full
projection audit (`--ensure`), compares it with the committed receipt, and checks
freshness again after the contracts. It never updates the committed receipt.

## Independent profile expectations

Every client runs `profile_corpus_golden_smoke.lua` against committed historical
expected values, retaining the real login, migrations, reset and codec pipeline.
The goldens are never regenerated by release-check. The codec also runs its
independent vector test. Current-code roundtrips remain supplementary.

`profile_defaults_oracle_smoke.lua` checks all 7,293 recorded factory and repair
paths (including type and absence), literal seed stages and the actual cold lazy
defaults providers. Repair uses the recorded mock group-placement context
(position mode/count/deltas/offsets/scale), because those values depend on
already-built frame geometry. The corpus independently pins login geometry.
Every other repair value is rebuilt. Changed seed declarations, repair defaults
and factory values are negatively probed against the unchanged fixture.

## Required providers

`flip_check.py` scans literal default-registry Require calls, including aliases
and deferred closures. Each release writes `<release-log>.required-registry.json`
with client, reader, line, binding/load/readiness phases, expected type and
observed provider file/phase/type. Actual core and Options exports supply the
providers; a keep name cannot supply one. Load-time core readers cannot borrow
an Options provider. Explicit third-argument namespace calls are separate from
this default-registry inventory. Dynamic names are not inferred.

`require_registry_smoke.py` pins the four Recovery APIs and negatively probes
deferred provider removal, wrong callable type and wrong readiness phase.
These contracts establish offline source/persistence behavior, not native WoW
rendering, combat/taint, SavedVariables file writes or measured in-game CPU.
