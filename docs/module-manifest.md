# One registration source for shipped modules and text

`tools/module-manifest.json` is the hand-edited registration source. Run
`tools/generate_module_manifest.py --write` after changing it. The same tool's
`--check` mode is static, compares exact bytes, writes nothing, and runs before
the Lua slot in `tools/release-check.ps1`.

The initial import at `c5fe4e3cb` preserves all 12 TOCs, 27 XML load manifests,
the load lock and the reviewed lists byte for byte, including CRLF, BOM state,
metadata, comments, conditional directives and ordering. No runtime code or
locale loader changes. `Bindings.xml` contains actions rather than file loads
and remains separately authored.

## Adding a Lua module

Create the implementation and add one record to `modules`, for example:

```json
{
  "path": "MidnightSimpleUnitFrames/Runtime/NewService.lua",
  "clients": ["Mainline", "Forever", "Vanilla", "Mists", "TBC"],
  "after": "MidnightSimpleUnitFrames/Runtime/MSUF_NumberFormat.lua"
}
```

Then run the generator. This inherits the anchor's load sites and inserts the
module immediately after it on the selected clients. The generator handles the
four TOCs or shared XML locations and the expanded client lock. The client
matrix supplies supported client names; Forever shares Mainline TOCs and uses
the existing `camelot` condition. Selecting only Mainline or only Forever adds
the appropriate single game-type directive.

If a Mainline module omits Classic clients, include a `reason` of at least 20
characters in the same record. That produces the flavor-exclusion rows. A
module intentionally retained outside every load graph instead has empty
`clients` and a `retained` object with `kind` and an evidenced `reason`.

A shared XML cannot selectively load a subset of its clients. Such a placement
fails explicitly; select a client-specific XML anchor or an anchor in the TOCs
(such as `Game/Shared/Initialize.lua`). The tool never broadens a client's load
set to make a placement succeed. Dependencies still determine the appropriate
anchor. Siblings follow manifest record order, and chained anchors are supported.

Existing records use `loads`: each entry names its owning `document`, original
line `order`, and a `line` template whose `{file}` is derived from `path`.
`documents` contains formatting and non-load scaffolding. These preserve the
historical layout, including differing Mists order, without copies of a module's
path in eight authored TOCs. Explicit sites and new `after` placement are
mutually exclusive. The declared client flags must equal the expanded graph.

New unresolved APIs or public exports remain reviewed decisions. The existing
review policies live in `reviewed_lists` in this same source. A module can add
evidenced TSV rows through `reviews`, keyed by the output TSV path, with an array
of complete tab-separated rows. The tool does not discover an unknown global
and silently approve it. Ratchet limits and feature baselines remain independent
quality policies and are never regenerated or relaxed by this tool.

## Adding visible text

Use the complete displayed English sentence as the localization key and add its
entry once to `MidnightSimpleUnitFrames/Locales/enUS.lua`. Run the generator.
`docs/locale-missing-keys.json` lists absent English keys for each other pack,
with a suggested Lua assignment for translators. Translations can be supplied
later in their existing packs; generated stubs are never loaded, never inserted
as fake translations, and never counted as completed translation work.

The existing localization metatable already returns the key for an absent
entry. That behavior, conditional locale parsing, saved menu-language selection
and companion-addon loading stay unchanged. The companion contains four TOCs
which reference the core packs; it has no second set of translation files.

The static lexer reads double/single quoted strings, Lua long strings, escaped
characters and table entries, and excludes comments. The report has no timestamp
or machine-specific path, so repeated generation is deterministic. Existing
non-English-only keys and translations are preserved.

## Inventory before and after

The master plan's historical **6 / 12** measures registration surfaces, not a
claim that every new file edits all six or all eight TOCs. The current inventory
below distinguishes unconditional registration from conditional policy changes.

| Surface before this lane | Required when | After this lane |
| --- | --- | --- |
| Core `_Mainline`, `_Vanilla`, `_Mists`, `_TBC` TOCs | A direct core load | Generated from the module record |
| Options' four corresponding TOCs | A direct Options load | Generated from the module record |
| Locale companion's four TOCs | Locale-pack load topology changes | Generated by the same tool |
| 27 XML manifests under both addons | A nested load; shared files can cover multiple clients | Generated from the module record |
| `tools/load-graph.lock` | Any ordered load change | Generated and checked statically |
| `tools/classic-flavor-load-exclusions.tsv` | Mainline loads a Lua file that some Classic clients omit | Generated from client flags and the module's reason |
| `tools/classic-unloaded-addon-lua.tsv` | A Lua file is deliberately retained without loading | Generated from the module's retained evidence |
| Former owned-paths, mirror overrides and mainline extras | Historical master-plan machinery | Already absent at this HEAD; no replacement manual list |
| `client-boot-globals.tsv`, `lua-global-reads.tsv`, `optional-globals.tsv`, `global-links-ledger.tsv`, `public-globals.tsv` | New API/global semantics, not merely a new file | Rendered from existing reviewed policy plus evidenced rows in the module record |
| `tools/classic-toc-identity.tsv` | Deliberate identity change, not a new Lua load | Rendered from the same source; original pins preserved |
| `quality_ratchet_baseline.json` and allowlist | Baseline promotion or a justified limit exception | No registration edit; new files already receive strict limits automatically |
| Feature inventory baseline and profile goldens | A deliberate feature/profile behavior change | No registration edit; existing tree scan includes new source automatically |
| 12 locale packs under core `Locales` | Previously each new text needed a matching entry | One English entry; missing-key report/stubs generated for the other 11 |
| Locale coverage/same-text exception lists | Intentional omissions or identical translations | Existing policy unchanged; no new per-key fallback exception required by the compact release check |
| Menu search index, defaults projections, media/catalog generators | Their respective content changes | Separate semantic generators, not file-registration sources; existing Options Lua outputs are outside C9 ownership |
| Smoke registry and release-version metadata | A new smoke or release, respectively | Separate explicit operations; neither is required merely to add a shipped Lua module |

Thus the required authored registration lists are **1 per new module / 1 per
new text**. Implementations, translations, policy review and content-specific
projections are separate work. The frozen historical gate is not changed or run;
its old all-packs translation assertions are not the new fallback contract.

## Verification

`tools/test_module_manifest.py` uses disposable, minimal static fixtures. It
checks insertion, client conditions, BOM/CRLF preservation, exclusions, locale
lexing and English-only additions. Stale-output probes first observe `--check`
return 1 without writing, then `--write` repairs the output and `--check` returns
0. Invalid client flags, anchors, cycles and unregistered Lua files fail closed.

The generator emits 49 outputs and runs without Lua, Git, external sources or
network access. The frozen `load-graph.lua` remains an independent compatible
reader; its historical lock header is deliberately kept byte-identical.

These are source/build contracts. They do not establish live WoW visual,
combat/taint or performance acceptance.
