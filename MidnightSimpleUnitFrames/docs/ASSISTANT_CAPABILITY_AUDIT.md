# Assistant Capability Audit

Generated from the current implementation after the Assistant registry split and the latest UI-control matrix pass.

## A. Executive Summary

What works now:

- The Assistant registry split is in place. `MSUF_AssistantRegistry.lua` is a small loader/manifest, and no Assistant registry file is a 300 KB monolith.
- The Assistant parser split is in place. `MSUF_AssistantParser.lua` now only owns the final parse pipeline and `A.Parse`, while parser domains live in focused files such as `MSUF_AssistantParser_Core.lua`, `MSUF_AssistantParser_Profiles.lua`, `MSUF_AssistantParser_Actions.lua`, `MSUF_AssistantParser_Registry.lua`, `MSUF_AssistantParser_Features.lua`, `MSUF_AssistantParser_Geometry.lua`, `MSUF_AssistantParser_Followups.lua`, and `MSUF_AssistantParser_Compound.lua`.
- `Shell/Menu2/MSUF_Menu2.xml` loads the Assistant loader, core registry, domain registry files, parser/runtime, and dashboard in order.
- The Dashboard Assistant input callback crash is fixed; the input field can call the parser path without nil callback errors.
- The offline registry harness loads `2604` settings and `128` actions.
- The strict UI matrix now reports `701` UI rows: `606` registered, `1` partial, `54` documented TODO, and `40` unmapped.
- In the current matrix there are no non-aura rows left with status `unmapped`, `partial`, or `todo`; the remaining matrix gaps are Aura/Group Aura rows that are intentionally out of scope for this pass.
- The registry-backed parser fallback now uses a token candidate index plus a small normalized-command candidate cache before exact setting scoring, avoiding repeated full registry scans while preserving value, ambiguity, and safety gates.
- Knowledge search now caches repeated page/query searches and precomputes normalized labels/categories for scoring. Snapshot-backed actions no longer duplicate profile DB snapshots when a profile snapshot already covers undo, and `assistant status` reports the last Assistant timing plus the last slow timing sample.
- Recent parity passes closed `AdvancedGameplay`, `GlobalFonts`, `GlobalBars`, non-aura `AdvancedColors` persistent settings/actions plus token selectors, `GroupLayout` including custom-anchor picker/direct frame-name control, GroupBars text tab/slot/move-together selectors, UnitText and UnitStatus selectors, GroupIndicators settings plus status/spell/corner selectors, profile staging fields, Group Copy category staging, NavRail section/search-intro state, profile action surface, and profile/gameplay/class-resource/dashboard setup diagnostics.
- Unitframe and castbar registry coverage remains broad: frame basics, anchoring, portrait, power, detailed text, transparency, range fade, load conditions, status icons, unit castbars, global castbar controls, previews/resets where shared helpers exist, copy/reset/preset flows, profiles, diagnostics, setup, navigation, undo/redo, and Edit Mode lifecycle controls.
- Parser smoke coverage now includes left-nav page shortcuts for Pet and Target of Target, NavRail section/search-intro actions, group-frame class color mode routing for `raidframe` and generic `group frames`, root castbar toggles, unit castbar detail toggles, compound shorthand such as shared scope/value/detail commands, mixed explicit on/off phrases, relative attribute lists, multi-scope castbar detail commands, and Menu2 selector-state commands including text move-together mode.
- Dashboard-path context now resolves short page-local and follow-up commands through the same Assistant input route the user uses in-game. Examples covered by smoke tests include `turn off name` on the Player page, `turn off name` on Group Health & Text with the current `gfScope`, and `turn off frame` after the Assistant has established a Player or Raid context.
- Confirmation prompts show and accept natural safe replies such as `do it`, `mach das`, and `go ahead`, plus natural cancels such as `never mind`, while still going through the same confirmation gate before executing. Profile copy/rename destination prompts also clean natural target replies such as `call it Raid Backup` or `to Raid Renamed` before asking for confirmation.
- Successful setting changes and snapshot-backed actions now explain what changed and include a direct next-step hint to type `undo` or continue with another follow-up request. Follow-up questions such as `what did you change` / `what did you do` report either the last setting value or the last executed Assistant action with its result.
- Unitframe, group-frame, castbar, class-resource, and focused Gameplay-helper visibility diagnostics now return actionable numbered fix choices for concrete stable causes such as disabled frames/castbars/resources/helpers, tiny dimensions, near-zero opacity, unit load-condition hide flags, Party Show While Solo, client-scene group hiding, Class Resource custom-width zero, Class Resource hide rules, and focused Gameplay helper toggles/sizing. Choosing a number runs the normal Assistant setting-change path, and single-choice diagnostics also accept natural follow-ups such as `fix it` / `mach das`.
- Numbered Assistant choices now support safe action-backed next steps as well as setting changes. Profile diagnostics use this to offer real follow-up navigation such as opening the Profiles page and repair actions such as clearing spec-profile mappings that point to missing profiles; Dashboard setup diagnostics use it for recovery tools and pending-workflow cancellation. These choices serialize through Assistant context and execute by number; single-choice prompts also show and accept natural replies such as `yes`, `open it`, or `apply it`, while multi-choice lists still require a specific number/label unless there is exactly one real repair for natural `fix it` wording.
- Search, FAQ, help, and bundled changelog data are reachable through the Assistant Knowledge path. Explicit Search/Find/Where/FAQ/Explain queries now go to Knowledge before page-open parsing, query verbs are stripped before scoring, release-note questions read from `MSUF_NS.MSUF_Changelog`, and no-match search/help requests return a deterministic Assistant no-match response instead of a fake setting failure. Public Search result openings now submit to the Assistant first, leaving the native Search page as an internal/fallback result renderer instead of a second user-facing command system.
- Menu2 shell controls are now counted by the UI matrix and mapped through shared helpers for close, minimize, maximize/restore, and minimized-bar restore. Dashboard disclosure headers, NavRail disclosure/search-intro state, Assistant-opened page back navigation, and native Menu2 page back/forward history are counted and mapped through shared Assistant navigation actions.
- The legacy Dashboard command-center fallback is no longer counted as an open non-aura gap: normal XML load order builds `MSUF.Assistant.BuildDashboardCard`, and the Dashboard-path smoke tests cover the real `A.Submit` input/result route.

Partial or missing:

- Full UI-row parity is not complete because Auras are intentionally out of scope until their backend lands. The remaining `unmapped`, `partial`, and `todo` matrix rows are Aura and Group Aura rows only.
- Aura whitelist-style operations and several aura style/placement/filter helper rows remain intentionally unmapped for the next Aura backend pass.
- Assistant-opened Dashboard page back navigation and native Menu2 page back/forward history are registered and covered by Dashboard-path smoke tests. Native menu-history undo/redo/session reset is registered through the same helpers as the NavRail history buttons.
- Short parser aliases for `help`, scoped `help for ...`, `copy profile NAME`, English `rename profile OLD to NEW`, and German profile rename phrases such as `profil Raid umbenennen` / `benenne profil Raid in Raid Neu um` are covered by smoke tests. Explicit source-profile copy and rename destination flows, unit copy, Unit Copy category staging, Group Copy category staging, and Dashboard-path `A.Submit` routing are also covered by focused smoke tests.
