# MSUF 6.0 Rewrite Feature Gate

Every feature that is reintroduced into the 6.0 UnitFrame rewrite must pass this order:

1. **Cold path first.**
   Resolve profile/database/menu state into `frame.MSUFSpec` and apply static frame layout, sizes, anchors, fonts, textures, fill direction, and feature enablement only from create/apply/config paths.

2. **Warm path only when state can change at runtime.**
   Event paths may update unit state such as health, power, threat, range, cast progress, aura deltas, status icons, and prediction values. They must read compiled spec/runtime fields, not profile tables.

3. **Cache before write whenever legal.**
   Expensive or redundant UI writes must be stamped with runtime-owned values: config generation, unit key, aura instance ID, frame dimensions, points, shown state, texture keys, font keys, color keys, and layout signatures.

4. **No secret-check runtime dependency.**
   The 6.0 rewrite does not call `issecretvalue` in the UnitFrame/Auras3 runtime. Hotpath code must use APIs that return normal Lua values for our frame scope or hand values directly to Blizzard setters. Features that require Lua secret introspection are not accepted in the rewrite hotpath.

5. **No Lua comparisons of Blizzard payload.**
   Runtime code must not compare, normalize, clamp, cache-diff, stringify-test, or branch on Blizzard unit/aura payload values that can be secret. Use the oUF/UUF pattern: pass values directly to Blizzard widgets (`SetValue`, `SetMinMaxValues`, `SetText`, `SetTexture`, `SetVertexColor`, `SetAlphaFromBoolean`) or use a Blizzard/C-side helper that returns the final value/state for that exact UI write. If a feature needs a yes/no decision, prefer Blizzard filter APIs or a compiled cold-path setting; do not infer it by comparing AuraData, health, power, range, duration, count, color, GUID, or dispel payload in Lua.

6. **No clean implementation, no feature.**
   If a feature cannot live in cold path or a narrow event path with legal caching, it is not restored in the rewrite until a better implementation exists.

7. **No compatibility wrappers as runtime design.**
   Compatibility globals may call the new core, but the feature itself must be implemented as a direct core element or compiled spec path.

## Core Rewrite Runtime Contract

- Compiled config, layout stamps, feature enablement, event ownership, and our own runtime booleans may be compared because they are MSUF-owned values.
- UnitFrame elements use contract v1: `IsEnabled(frame, spec)`, `Create(frame, spec)`, `Apply(frame, spec)`, `Update(frame, event, unit, ...)`, `Disable(frame)`, `GetEvents(frame, spec)` / `GetUnitlessEvents(frame, spec)`, plus optional `hotLane` and `runtimeLane` metadata. `UF.RegisterElement` stamps `element.id` and `element.contractVersion` so new elements can participate without Core string edits.
- Blizzard payload from unit/aura APIs is write-through by default. Health, power, prediction, aura counts, aura colors, icon textures, durations, stealable state, range answers, and dispel state must flow directly into C-side APIs or Blizzard widget setters.
- Cache is still allowed for cold/static data: frame geometry, font keys, texture keys, anchors, enabled flags, element ownership, aura container layout, button size, and visible button count.
- Cache is not allowed when it requires comparing secret payload values in Lua. In that case, do the oUF/UUF direct write or drop the feature until Blizzard exposes a C-side-safe path.
- Any future optimization that reintroduces payload comparisons must be rejected during code review, even if it looks cheaper in Lua.

## Current Examples

- `reverseFillBars`: cold-path per-unit setting. Compiled into `MSUFSpec.health.reverse` and `MSUFSpec.power.reverse`, then stamped through `SetReverseFill` on Health, Power, and Prediction bars during element apply.
- `smoothFill` / `powerSmoothFill`: cold-path per-unit settings. Compiled into `MSUFSpec.health.smooth` and `MSUFSpec.power.smooth`; element apply stamps the 12.0 statusbar interpolation enum once, and the existing bar value path passes it through without Lua animation.
- HP/Power text abbreviation: compiled slot settings choose short-number mode; runtime uses Blizzard's 12.0 number abbreviation API when available and falls back only on older clients.
- Portraits: render mode, class pack, shape mask, size override, offsets, background, and border/fill mode are compiled into `MSUFSpec.portrait`. The element uses Blizzard's `SetPortraitTexture` for 2D portraits, Blizzard atlas class icons for the default class style, and prebuilt RONDO visual tables for custom class packs. No GUID/secret cache, no old portrait wrapper/event timer path.
- Status icons: leader/assist, raid marker, level, raid-group name, elite/rare, status text, combat, resting, and incoming resurrection compile into `MSUFSpec.status`. Layout, symbol paths, style, size, layer, and enabled flags are cold-path; runtime only reacts to registered Blizzard events for enabled indicators.
- Load conditions: mounted, vehicle, resting, combat, out-of-combat, stealth, solo, group, and instance flags compile into `MSUFSpec.load`. Secure macro-compatible rules are emitted as one `RegisterStateDriver(frame, "visibility", ...)` expression per frame, so combat/group/mount/rest/stealth visibility is handled by Blizzard's secure driver instead of Lua polling. `In instance` is the only warm-path rule because macro conditionals do not expose instance state; it registers only zone/login/regen events and swaps the visibility expression out of combat. Preview mode refreshes the same driver and force-shows non-player frames without adding hotpath work.
- Opacity: frame alpha and combat/out-of-combat alpha compile into `MSUFSpec.alpha`. The old layer-fade/preserve-HP/portrait-alpha backend is removed from the UnitFrame rewrite. Runtime writes only the root frame alpha, and combat events register only when alpha differs between combat states.
- Unit range fade: removed from the UnitFrame backend. Alpha now owns only configured opacity/combat-state fading; there is no unitframe range library, range event registration, spell/interact range fallback, range ticker, range `OnUpdate`, castbar range path, or aura range path.
- Cooldown-manager anchoring: unitframe anchor targets are compiled as `anchorToUnitframe` / `anchorFrameName` and resolved only in the protected Apply path. The factory can anchor directly to MSUF frames or cooldown viewer frames; combat changes are deferred through the existing `PLAYER_REGEN_ENABLED` apply queue. BetterCooldownManager receives the real `MSUF_player`, `MSUF_target`, `MSUF_focus`, `MSUF_pet`, ToT, focus target, and boss frame names directly, without proxy frames or sync scripts.
- Absorb display: display mode, absorb anchoring, heal-prediction anchoring, textures, and opacity compile into `MSUFSpec.prediction`. The runtime uses Blizzard's 12.0 `UnitHealPredictionCalculator` clamp modes when available, so follow/overflow behavior is calculated C-side. Prediction values are normalized once and then stamped before statusbar writes.
- Frame outline: thickness and colors compile into `MSUFSpec.border`. Static outline geometry and color apply in the cold path; aura/threat border events register only when those dynamic highlight modes are enabled.
- Detached power bar: height, detached size, offsets, layer, class-resource anchor/sync, cooldown-manager width frame, border, smooth fill, and text-on-bar layout compile into `MSUFSpec.power` / `MSUFSpec.text`. The Power element only stamps layout in Apply; live events update the bar value and color. Non-player power text can be combat-throttled without delaying the actual bar value.
- Boss edit preview: boss layout delta is a compiled/cold geometry helper shared by real boss frames, Edit Mode drag math, boss unitframe preview visibility, and boss castbar preview positioning. Auras remain parented to their boss frame, so no separate aura mover loop is needed when spacing/layout changes.
- Name color runtime: `nameClassColor` and `npcNameRed` compile into `MSUFSpec.text`. Runtime name updates read only the spec plus cached class/NPC color tables; no DB/menu reads are allowed in the text event path.
- Name shortening: shared and per-unit font override settings compile into `MSUFSpec.text`. Player names stay excluded unless explicitly overridden. Runtime truncates only on name refresh, uses a cold rule stamp, and keeps UTF-8 walking local to that rare path.
- Target-of-target inline text: ToT inline enablement, separator, color mode, and ToT name-shortening rules compile into the target frame `MSUFSpec.text.inlineToT`. When disabled, no inline fontstrings are shown and no extra Text events are registered.
- Class resources: main class-resource enablement compiles into `MSUFSpec.classPower` for the player only. The controller resolves resource type, layout, texture, font, prediction, and mode-specific event profile only when Class Resources or Alt Mana are enabled. Disabled class resources must not keep spec/form/vehicle events, mode tickers, Warrior Whirlwind events, Balance Druid prediction events, texture refresh loops, or detached bridge refreshes alive.
- Auras3: delta-first runtime. Delta updates drive visible button refresh; icon/color/count payload is keyed by aura instance ID and not routed through `issecretvalue`.
- UnitFrame position/size: cold-path only, combat-deferred and stamped.

## Feature Performance Passes

- Load conditions: accepted. Profile flags are compiled once into `MSUFSpec.load`; no `MSUF_DB` reads, aura scans, timers, or `OnUpdate` are used in the runtime element. The normal path is one stamped secure visibility driver per frame. Lua events are only registered for active rules, and only `In instance` needs a warm event path because secure macro conditionals do not expose instance state. Combat changes to the driver are deferred through the existing UF dirty/apply path.
- Opacity: accepted. The old UnitFrame transparency backend was deleted instead of wrapped. The rewrite now has one compiled Alpha element: root-frame alpha only, combat events only when in/out combat values differ, no layer/preserve/portrait alpha branches, no DB/menu reads, timers, broad refresh loops, or `OnUpdate`. Disabled/static alpha unregisters the element and resets stale child alpha stamps left by older profiles.
- Unit range fade: removed for UnitFrames. The Alpha element is kept focused on base opacity and combat-state changes; group-frame range fade remains a separate group-only backend.
- Cooldown-manager anchoring: accepted. Unhalted's useful part is the direct anchor contract, not a runtime mover. MSUF now registers real UnitFrame globals with BetterCooldownManager and removed the old third-party proxy/snap layer. UnitFrames can be anchored to global, another MSUF frame, a custom picked frame, or the cooldown viewers from the cold Apply path. If the cooldown manager loads after MSUF, one cold apply re-resolves the selected viewer anchor, with combat defer if needed. Spell expansion moves anchored frames through Blizzard's native anchor system; there is no per-spell Lua, polling, timer, `OnUpdate`, or proxy synchronization.
- Absorb display + frame outline: accepted. Absorb/heal/incoming prediction stays isolated in the `Prediction` element and registers only prediction, absorb, max-health, connection, and conditional health events when a clamp mode depends on current or missing health. Anchor modes are cold layout stamps; follow modes anchor to the current HP/Prediction statusbar texture and use 12.0 calculator clamp modes for missing-health versus overflow behavior. Absorb/heal-absorb textures are Bars-scope aware and resolve in the cold apply/render path. Absorb texture test mode is compiled into `MSUFSpec.prediction.test`, uses fixed preview values, registers no unit events while active, and respects the Bars scope (`shared`, unit keys, boss, party, raid). Prediction overlay bars stamp frame strata/level against the HP bar and only follow a visible incoming-heal bar, so hidden heal prediction cannot pull absorb off-frame or behind the unitframe. Absorb text was removed from the 6.0 runtime; absorb events now update bars only. The outline slider now owns 6.0 static outline enablement, so old `useBarBorder=false` profiles cannot leave the new outline visually dead when thickness is greater than zero. Static outline writes happen in `Borders.Apply`; dynamic aura/threat checks run only when those highlight features are enabled.
- Detached power bar: accepted. The new path removes the old DB-width mutation from ClassPower layout and uses compiled spec fields plus the live class-resource frame width only during Apply/layout refresh. Detached background and border regions are parented to the power statusbar so layer changes do not fight the main UnitFrame. Class-resource anchor/sync and cooldown-manager width modes resolve through cold layout stamps; ClassPower only requests a power-layout refresh when its own width/height stamp changes. Power events still write bar value immediately, while non-player power text formats at most every configured throttle interval during combat; player power text remains unthrottled.
- Boss edit preview: accepted. The preview path now uses secure visibility-driver state instead of manual show loops as the source of truth for `boss1..5`. `MSUF_PreviewTestMode`, `MSUF_BossTestMode`, and the Menu2 boss preview flag all flow through the same `ApplyBossPreviewState` cold path, which refreshes only boss visibility/runtime, refreshes only boss aura units when Auras3 exposes unit refresh, and then asks Castbars to redraw the boss preview. Castbar detached stacking now uses the same boss layout delta as the UnitFrames, so vertical/horizontal order and spacing stay aligned. No `OnUpdate`, aura scan, or DB read was added to the UnitFrame hot path.
- Name color runtime: accepted. Player/class and NPC/reaction name-color options are now compiled into `MSUFSpec.text`, with class and NPC color lookup prebuilt in the settings cache. Extra faction/classification events are registered only for NPC/reaction coloring; class-only names keep the normal name-update event set. The hot text path does no DB/menu reads and does not touch HP/power text throttling.
- Name shortening: accepted. The old 5.52 behavior is restored without calling the old runtime. Shared and font-override settings are resolved during config compile, including max length, keep-start/keep-end side, ellipsis, and the player exclusion rule. The Text element registers no new events; it shortens only when the unit name changes or the cold rule stamp changes. Names cache raw value plus rule stamp, so faction/color-only events do not re-truncate.
- Target-of-target inline text: accepted. The feature is owned by the Text element, not a compatibility wrapper. Config compile resolves the targettarget DB settings into `target.MSUFSpec.text.inlineToT`, including custom separator cleanup, color mode, target/tot name-color flags, and ToT shortening rules. Disabled inline text registers no extra events and hides any stale inline regions. Enabled inline text adds only `UNIT_TARGET` on the target frame plus unitless name/classification refresh filtered to `targettarget`; random unit events return before string work. The runtime caches raw ToT name plus the inline rule stamp, so color-only and unrelated unit events do not reformat.
- Class resources: accepted. `showClassPower=false` now prevents player spec compile from enabling the ClassPower bridge and prevents the controller from resolving resource type, spec overrides, UnitPowerMax, fonts, textures, layout, or mode update functions. Runtime events are rebound from the active mode profile and are fully unregistered when Class Resources and Alt Mana are both off; the central tick frame is stopped; delayed PEW relayout is skipped. Warrior Whirlwind and Balance Druid prediction/color modules now bind their own eventframes only while their feature is active, and Balance prediction spellcast events are additionally removed when prediction is disabled. Cold public refresh calls remain available so menu/profile changes can re-enable the feature without leaving disabled-state hotpath work behind.
- HP/Power bar interpolation guard: accepted. StatusBar 12.0 interpolation remains fully Blizzard/C-side and is passed only to `SetValue` for real value-delta events (`UNIT_HEALTH`, `UNIT_POWER_UPDATE`, `UNIT_POWER_FREQUENT`), matching the oUF/Unhalted pattern. Min/max writes are immediate. Apply, ForceUpdate, max-value changes, and unit-swap correction paths do not animate; they call `SetToTargetValue` only if this bar previously started a C-side interpolation, so refresh correction avoids stale visual targets without adding a constant snap call.
- UnitFrame event ingress: accepted from the 2026-05-25 Perfy trace. The trace showed `FrameOnEvent` running 65,197 times in 30 seconds while real element updates ran only 4,359 times. Per-frame event registration was replaced with one central UnitFrame event driver that registers each event once, routes unit-token events directly to `UF.frames[unit]`, and only fans out to frames that explicitly have unitless owners. This keeps the element-owned event model but removes the broad per-frame dispatch multiplier from idle/combat hot paths.
- Text/status micro-elements: accepted. The old broad Text and Status runtime paths are now cold layout owners only. Runtime ownership is split into `NameText`, `HealthText`, `PowerText`, `InlineToT`, `RaidMarkerIndicator`, `LeaderIndicator`, `LevelIndicator`, `RaidGroupIndicator`, `EliteIndicator`, `StatusTextIndicator`, `CombatIndicator`, `RestingIndicator`, and `IncomingResIndicator`. Each mini-element declares only the events it needs, disabled mini-elements unregister completely, and the central driver dispatches directly to the owning mini-element instead of refreshing all text or all indicators. The old status event arrays and `UNIT_COMBAT` path were removed from the UnitFrame rewrite.
- Perfy dispatch/cache pass: accepted. The 2026-05-25 trace showed `UnitEventMatchesFrame`, `ResolveOwnerUnit`, `BindAuraAPIs`, `SortAuras`, and `UF.IsSecretValue` wrappers as repeated Lua overhead around otherwise narrow updates. Unit-token dispatch now inlines frame matching, health/power hot paths reuse the already resolved unit, unitless ownership is tracked in its own registry, UnitFrame/Auras3 runtime no longer calls `issecretvalue`, and Auras3's default Top-N aura ordering uses a bounded insertion path instead of repeatedly invoking the generic sorter. No DB reads, timers, `OnUpdate`, or feature wrappers were added.
- External perf review pass: accepted where it improves the rewrite contract. `DispatchFrameEvent` keeps the O(1) unitless-owner check, Auras3 full scans no longer fall through to the 80-index fallback when `GetAuraSlots` already answered with zero auras, aura API binding happens once per element update, harmful-lane state is compiled on the lane instead of using `string.find` per aura, `UF.ElementEnabled` is shared by Core and Factory, and runtime refresh masks reuse shared sentinel tables. `UNIT_TARGETABLE_CHANGED` is only registered by the legacy Auras3 fallback driver; in the 6.0 UF runtime the central UF driver owns boss refresh.
- Auras3 lane hotpath pass: accepted. Lane filter strings, PLAYER-filter variants, filter callbacks, and post-process callbacks are resolved/stamped on the lane instead of rebuilt per aura. Delta `addedAuras` are routed through Blizzard's `IsAuraFilteredOutByInstanceID` filter path, not through secret helpful/harmful payload fields. Disabled/empty lanes now clear once and stay inert until config/full-update changes. Full scans still use `C_UnitAuras.GetAuraSlots` first and only fall back to index scans when that API path is unavailable.
- Unhalted/oUF comparison pass: accepted. MSUF keeps its own core, but adopts the useful shape: no inactive aura container should be a runtime update target. Auras3 now stores Buff/Debuff lanes separately and exposes only enabled lanes to the root runtime; disabled lanes are cleared once and then skipped instead of receiving every `UNIT_AURA`. The UnitFrame Auras element also refuses registration when the Auras3 unit config has no visible Buff or Debuff lane. The broad Text owner is now cold/layout-only and only enabled when at least one name, HP, power, or inline-ToT text feature exists.
- UnitFrame hotpath review notes: accepted. Health/Power bars now cache unit status on the frame and refresh it only on non-health/power state events or unit swaps; `HealthColor` reads the cached dead/connected/player/NPC-kind state instead of re-querying those APIs on every eligible health update. The UnitFrame/Auras3 runtime skips `issecretvalue` entirely for player, target, focus, boss, ToT, and aura paths. Prediction layout no longer builds a garbage string key per update; it stamps mode, reverse, anchor target, and width directly. Generic UnitFrame dispatch keeps owner maps for hot/unitless routing but uses a flat per-event element list for the non-hot path.
- Health/secret payload correction: accepted. The no-`issecretvalue` rule does not mean treating Blizzard payload as normal Lua numbers. Health now follows the oUF/Unhalted 12.0 pattern: one per-frame `UnitHealPredictionCalculator`, `UnitGetDetailedHealPrediction`, direct `SetMinMaxValues` / `SetValue`, and C-side `EvaluateCurrentHealthPercent` gradient color. HP/Power/Prediction statusbar values are no longer normalized, compared, or cached in Lua. Numeric text formatting also avoids value comparison caches; layout/config caches remain cold-path only.
- Auras3 secret payload correction: accepted. Aura button refresh now mirrors oUF/UUF's 12.0 pattern: `GetAuraApplicationDisplayCount` goes directly into `FontString:SetText`, `GetAuraDispelTypeColor` goes directly through `ColorMixin:GetRGBA` into the overlay, icons are assigned directly, and stealable state uses `SetAlphaFromBoolean` when available. The runtime no longer compares stack-count strings, icon/color payload stamps, or `canActivePlayerDispel` aura fields. Border dispel state is produced by the debuff lane via Blizzard's filter API and consumed by Borders without a second AuraData scan.
- Auras3 blacklist: accepted for Blizzard-exposed/declassified spell IDs only. The Blacklist UX writes prepared spell IDs from spell links, resolvable names, or the Blizzard-exposed non-secret aura presets into the profile. Runtime compiles the active shared/per-unit list into one hash per config generation and attaches it to each aura lane. Disabled/empty blacklists add zero per-aura work; active blacklists do one `tonumber(spellId)` plus hash lookup before sorting/rendering. No live aura-name comparison, tooltip parsing, DB read, or duplicate aura scan is allowed. Mythic+ teleport spells are not preset until Blizzard/Wowhead publish exact IDs.
- Name text secret-payload correction: accepted. `UnitName` for target-derived and boss units can be a secret string, so live UnitFrame name text now follows the oUF/UUF pattern and passes `UnitName(unit)` directly to `FontString:SetText`. Runtime name code must not cache-diff, compare against nil/empty, UTF-8 walk, shorten, or concatenate live `UnitName` payload. Name shortening remains a cold/profile rule, but it cannot legally inspect live secret names until Blizzard exposes a C-side truncation/helper path; visual clipping must be handled by fontstring geometry instead of Lua string operations.
- GroupFrame secret-payload pass: accepted for direct-write paths. GroupFrame aura stacks, aura cooldown text color, dispel-border color, health/power values, prediction/absorb bars, power color, phase icon, and target-range alpha were converted away from `issecretvalue` gates and payload compare caches where the value can be passed straight to Blizzard widgets or C-side helpers. Remaining legacy GroupFrame features that still need Secret guards are not clean rewrite patterns: custom Aura blacklist by `spellId`/name, HealerBuff family matching, SpellIndicator aura matching, CornerIndicator aura matching, StatusOffline dead/AFK/DND text, GroupNumber roster subgroup checks, Render preserve-missing-HP math, and GUID-based target/focus lookup. Those require a Blizzard filter/state API or a feature redesign; otherwise they must be dropped from the 6.0 hotpath rather than "optimized" with Lua payload comparisons.
- GroupFrame name/linked-aura correction: accepted. Live group-frame names now mirror UnitFrames: `UnitName(unit)` is written directly to the FontString with no Lua truncation, nil/empty comparison, cache-diff, or menu name payload forwarding. Preview/fake names may still use `GF.TruncateName` because they are MSUF-owned strings. The old SpellIndicator fallback that parsed localized tooltip text and matched it against party/raid `UnitName` is removed; linked aura support is limited to API/ID/filter paths that do not compare secret names.
- UnitFrame hotroute refactor: accepted. Element events still register from each element, but Core now compiles a per-frame/per-event route in the cold registration path. `Health`, `Power`, `HealthText`, and `PowerText` expose `hotLane` metadata so the dispatcher can keep value handoff optimized without hardcoding event-to-element strings in `DispatchHotFrameEvent`. Runtime refresh uses the same idea through `runtimeLane` metadata (`health`, `power`, `name`, `inline`, `portrait`, `alpha`, `status`, `prediction`, `auras`, `borders`) instead of a hardcoded owner table. All other event owners use the same flat generic route array, preserving disabled-feature zero overhead and avoiding per-event `pairs` scans or broad element refreshes.
- Text engine split + throttle pass: accepted. The former monolithic Text element is split into `MSUF_UF_Text_Format.lua` for pure value/slot formatting, `MSUF_UF_Text_Layout.lua` for FontString/layer/color layout, and `MSUF_UF_Text_Runtime.lua` for element glue/runtime updates. HP/Power text throttling no longer creates `C_Timer.After(function() ...)` closures; it uses one static OnUpdate queue that is enabled only while throttled text frames are pending and turns itself off when empty.
